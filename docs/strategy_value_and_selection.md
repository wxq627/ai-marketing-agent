# 策略价值与预算选择说明

## 1. 功能定位

历史响应模型负责预测客户在一次触达后打开、点击、转化和退订的概率。策略价值模块不重复训练模型，而是把这些概率与业务收益、权益成本、风险和长期价值结合，得到每个候选策略的预期净价值。

候选粒度为：

```text
客户 x 可投放产品/权益 x 合规可用渠道 x 活动
```

对于分期、消费权益和唤醒活动，候选中的“产品/权益”是活动本身，不会把不相关的高年费卡种拿来参与 LTV 排序；只有卡升级活动才会比较具体卡产品。

## 2. 价值公式

```text
预期净价值
= P(转化) x 单次边际收益
+ P(长期留存) x 客户基准 LTV x LTV 增量比例
- 渠道触达成本
- 权益预期成本
- P(退订) x 客户基准 LTV x 流失损失比例
- 投诉风险 x 投诉损失
- P(转化) x P(违约|转化) x 预期信用损失
```

其中：

```text
P(长期留存) = P(转化) x 客群长期留存率 x (1 - P(退订))
```

该概率是 Demo 阶段的可解释代理指标；后续可替换为专门训练的激活/唤醒模型。

### 权益成本触发规则

| 活动类型 | 权益成本触发点 | 原因 |
|---|---|---|
| 消费券、权益活动 | `P(点击)` | 客户点击/领取后就可能产生权益成本 |
| 分期、升级、激活 | `P(转化)` | 客户办理或达标后才产生主要成本 |

因此，打开率和点击率不会再与转化率相乘。当前 `P(转化)` 已经是触达后直接预测的转化概率；点击率只用于判断前置权益成本。

## 3. LTV 估计

Demo 使用透明的规则估计 36 个月基准 LTV：

```text
基准 LTV
= 月消费 x 生命周期月数 x 交易边际收益率
+ 年费 x 生命周期年数 x 年费边际收益率
```

再按客户价值等级和风险等级调整，并设定最低 LTV 下限。所有参数均位于：

```text
services/strategy-agent/config/strategy_value_policy.json
```

这不是生产级 LTV 模型，但它使“短期不赚钱、长期值得唤醒的客户”能够在排序中被保留。后续可用真实生命周期收入、流失标签和风险损失训练生存分析或回归模型替换。

## 4. 预算约束选择

选择器按以下顺序排序：

```text
预期净价值 / 预算成本（价值密度）降序
预期净价值降序
```

然后依次纳入候选，并执行硬约束：

1. 预期净价值必须为正。
2. 累计预算成本不得超过活动预算。
3. 渠道投放人数不得超过渠道日容量。
4. 同一客户在同一轮只保留一个候选，防止多产品、多渠道重复打扰。
5. 客户营销授权和频控已在候选生成前由合规模块过滤。

Demo 数据没有家庭账户标识，因此家庭去重会在结果中明确标记为 `not_available_in_demo_data`，不会假装已经完成。

## 5. 调用接口

```text
POST /api/strategy/optimize/real-data
```

请求示例：

```json
{
  "campaign_id": "CAMP_2026_DOUBLE11",
  "budget": 200000,
  "customer_limit": 200,
  "selected_sample_limit": 100,
  "evaluation_time": "2026-07-17 12:00:00"
}
```

响应包含：

- 参与评分的候选数量。
- 最终选中人数、预算使用额、预期净价值和预期转化人数。
- 按渠道的使用量。
- 被预算、容量、客户去重或负价值规则排除的数量。
- 每个入选候选的模型概率、LTV、收入、成本、风险损失和净价值拆解。

运营网页中的“价值优化”按钮会调用该接口，并将结果保存为策略草稿。运营确认后点击“发布给 C 端”，C 端只会读取优化后入选客户的策略上下文。

## 6. 模型产物初始化

模型文件不提交到 Git。新电脑或新环境进入项目后，运行：

```powershell
cd services\strategy-agent
.\scripts\bootstrap_demo.ps1
```

该脚本会检查四个模型产物；缺失时自动基于项目 A 的原始数据重新训练。完成后再运行：

```powershell
C:\Python314\python.exe app.py
```

## 7. 反馈沉淀

`POST /api/strategy/feedback` 现在会把 C 端回传的事件保存至 SQLite 的 `strategy_feedback_event` 表，并继续返回原有的汇总建议。运营端可通过以下接口查询：

```text
GET /api/strategy/feedback?strategy_version=STR_...&limit=100
```

后续重训时，应将该事件表与活动、渠道、客户授权状态及转化事实表按版本和时间窗口关联。

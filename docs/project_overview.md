# AI智能营销Agent项目总体需求

## 1. 项目定位

本项目面向信用卡业务全生命周期运营场景，建设一套“数据/知识底座 -> 策略编排大脑 -> C端交互触达”的 AI 全链路智能营销平台。

平台目标不是单点做一个客服机器人，也不是只做知识库，而是形成从客户认知、策略制定、客户触达、效果反馈到持续优化的闭环能力。

## 2. 总体业务目标

1. 支持信用卡新户获客、存量经营、沉睡激活、分期促动、权益推荐、生命周期管理等核心营销场景。
2. 将原本依赖人工经验的营销配置流程，升级为 AI 辅助的智能决策流程。
3. 通过统一知识、客户画像、策略生成、客户交互和反馈回流，提高营销效率、转化效果和合规可控性。
4. 形成可解释、可追问、可执行、可复盘的端到端智能营销平台。

## 3. 三个子项目划分

### 项目一：企业知识引擎与记忆中心（Knowledge Agent）

项目一是整个系统的“认知底座”，负责提供企业知识、产品规则、合规约束、客户画像、客户行为记忆和实时意图识别能力。

核心需求：

1. 接入多源数据：银行核心系统、CRM、App 埋点、客服通话文本、营销活动记录等。
2. 构建 OneID 客户主体档案，统一手机号、证件号、设备 ID 等身份标识。
3. 沉淀客户画像：基本属性、额度情况、生命周期阶段、价值等级、风险等级、权益偏好、渠道偏好等。
4. 构建动态行为记忆：近期消费变化、搜索行为、客服咨询、点击领取、拒绝投诉等事件流。
5. 构建企业知识库和 GraphRAG：关联客户、产品、权益、活动、规则、权限、合规要求。
6. 输出标准接口：CustomerProfile、IntentVector、EventSequence、DomainKnowledge。

### 项目二：策略编排与推荐大脑（Strategy Agent）

项目二是整个系统的“经营大脑”，负责把项目一提供的数据和知识转化为运营人员可用、C端可执行的营销策略。

核心需求：

1. 理解运营人员自然语言目标，并拆解为客群、产品、权益、渠道、时机、预算、频控、合规约束等结构化要素。
2. 基于客户画像和行为数据进行群像刻画，识别目标客群特征、规模、潜在价值和风险。
3. 进行智能客群圈选，预测客群规模、响应概率、转化率、ROI 和投诉风险。
4. 生成可解释策略，包括推荐客群、推荐理由、权益规则、渠道路由、预算分配、触达节奏和 A/B 实验方案。
5. 支持运营人员追问和微调，例如调整预算、风险阈值、渠道偏好、目标人群范围。
6. 输出标准策略包，供项目三执行触达。

### 项目三：C端智能交互与触达执行（Marketing Agent）

项目三是整个系统的“手脚与感官”，负责把项目二生成的策略转化为客户可感知的营销内容和服务交互。

核心需求：

1. 根据策略包生成个性化 SMS、App Push、外呼话术、客服话术、权益海报等内容。
2. 在 App、微信小程序、客服会话等 C 端场景中与客户交互。
3. 至少包含三类智能体：查询类 Agent、服务类 Agent、营销类 Agent。
4. 根据项目二策略判断能否推荐、推荐什么、怎么说、哪些内容不能说。
5. 支持多轮渐进式触达，例如首次 Push 未响应后切换文案或渠道重试。
6. 收集曝光、点击、转化、拒绝、投诉、对话摘要等反馈，回流项目一和项目二。

## 4. 总体闭环流程

1. 项目一沉淀客户画像、企业知识、产品规则、权限和合规约束。
2. 项目二读取项目一的数据和知识，完成群像刻画和营销策略生成。
3. 项目三接收项目二的策略包，执行客户触达和智能对话。
4. 项目三把客户行为反馈回流给项目一更新画像，也回流给项目二复盘优化策略。
5. 项目二基于反馈迭代人群、渠道、预算、话术和实验方案。

## 5. 关键验收要求

1. 三个子项目之间必须有清晰接口和标准数据格式。
2. 项目二必须能展示从运营目标到结构化策略包的完整链路。
3. 项目二输出的策略必须可解释，不能只是给出结果。
4. 系统必须体现银行营销场景中的合规、权限、频控、风险和客户体验约束。
5. 最终需要能展示：客户画像如何被使用、策略如何生成、C端如何执行、反馈如何回流。

# 项目二日志文档：策略编排与推荐大脑（Strategy Agent）

## 1. 项目二定位

项目二负责建设 B 端“策略编排与推荐大脑”，连接项目一的数据/知识底座和项目三的 C 端触达执行模块。

一句话定位：

> 项目二把项目一提供的客户画像、企业知识、产品规则和合规约束，转化为运营人员可理解、C端可执行、后续可复盘的营销策略包。

## 2. 项目二核心目标

1. 支持运营人员用自然语言提出营销目标。
2. 自动拆解营销目标，识别客群、产品、权益、渠道、时机、预算、频控和合规约束。
3. 基于项目一提供的数据进行群像刻画和客群圈选。
4. 生成可解释营销策略，包括人群、渠道、预算、权益和内容大纲。
5. 输出标准 JSON 策略包给项目三执行。
6. 接收项目三反馈数据，完成策略复盘和下一轮优化建议。

## 3. B端功能模块日志

### 模块一：经营目标理解

目标：

将运营人员的大白话需求解析为结构化策略任务。

示例输入：

```text
针对高价值年轻客群制定双十一分期促动方案，预算 80 万，要求控制投诉风险。
```

解析输出：

```json
{
  "objective": "提升分期转化",
  "target_group_hint": "高价值年轻客群",
  "product": "credit_card_installment",
  "scenario": "双十一消费场景",
  "budget": 800000,
  "risk_preference": "low",
  "constraints": ["控制投诉风险", "遵守频控", "文案合规"]
}
```

技术点：

- LLM 意图理解
- Prompt Engineering
- 结构化输出 JSON
- 参数校验

### 模块二：群像刻画与客群圈选

目标：

基于项目一提供的 CustomerProfile、IntentVector、EventSequence，对目标人群做群像分析和圈选。

需要分析的维度：

- 客户价值：消费金额、额度使用率、资产/贡献度
- 生命周期：新户、活跃、沉睡、流失风险
- 行为偏好：餐饮、商旅、线上支付、分期、权益领取
- 渠道偏好：App、短信、企微、外呼
- 风险约束：投诉风险、频控命中、授权状态
- 实时意图：近期咨询、搜索、浏览、点击、拒绝行为

输出内容：

- 推荐客群名称
- 客群规模
- 客群典型特征
- 预估响应率
- 预估转化率
- 预估 ROI
- 排除人群原因

技术点：

- 用户分群
- 规则过滤
- 响应率预测
- 转化率预测
- 风险预测
- 客群可解释分析

### 模块三：策略生成与预算分配

目标：

根据客群画像、产品规则、渠道成本和合规约束，生成可执行营销策略。

策略要素：

- AudienceSegment：目标客群
- BenefitRule：权益规则
- ChannelRouting：渠道路由
- BudgetAllocation：预算分配
- ContactPlan：触达节奏
- ComplianceGuard：合规约束
- ExperimentPlan：A/B 实验方案

示例输出：

```json
{
  "audience_segment": "高消费高活跃分期潜力客群",
  "benefit_rule": "分期手续费折扣券",
  "channel_routing": [
    {"channel": "app_push", "budget_ratio": 0.5},
    {"channel": "sms", "budget_ratio": 0.2},
    {"channel": "wechat", "budget_ratio": 0.3}
  ],
  "contact_plan": "7天内最多触达2次",
  "experiment_plan": "10% 对照组，90% 策略组"
}
```

技术点：

- 多目标优化
- 推荐排序
- 预算分配
- 渠道策略
- MCP 工具调用
- LangGraph 状态机编排

### 模块四：可解释策略推荐与追问

目标：

让运营人员知道“为什么推荐这批人、为什么用这些渠道、为什么这样分预算”。

输出解释：

- 推荐理由
- 命中规则
- 使用的数据来源
- 风险提示
- 替代方案
- 可调整参数

支持追问：

```text
如果预算减少到 50 万，策略怎么变？
如果只用 App 渠道，预估 ROI 会下降多少？
如果投诉风险阈值更严格，客群规模还剩多少？
```

技术点：

- LLM 推理
- 策略状态管理
- 多轮对话上下文
- Redis 状态持久化
- 结构化解释生成

### 模块五：策略包输出与下发

目标：

将最终策略封装为标准 JSON，交给项目三执行。

策略包必须包括：

- CampaignMetadata
- AudienceSegment
- BenefitRule
- ChannelRouting
- BudgetAllocation
- ContentBrief
- ComplianceGuard
- ExperimentPlan
- CallbackConfig

技术点：

- REST API
- JSON Schema
- 字段校验
- 版本管理
- 接口联调

### 模块六：反馈复盘与策略优化

目标：

接收项目三回传的曝光、点击、转化、拒绝、投诉和对话摘要，分析策略效果并生成下一轮优化建议。

复盘指标：

- 曝光率
- 点击率
- 转化率
- ROI
- 投诉率
- 渠道成本
- 客群贡献
- 文案效果
- 对照组差异

输出内容：

- 哪些客群效果最好
- 哪些渠道性价比最高
- 哪些话术需要调整
- 哪些人群应降频或排除
- 下一轮策略建议

技术点：

- A/B Test 分析
- 效果归因
- 指标看板
- 策略迭代
- 数据回流

## 4. 开发里程碑

### 第 1 阶段：接口与数据结构确定

任务：

- 明确项目一给项目二的数据字段
- 明确项目二给项目三的策略包字段
- 明确项目三回传项目二的反馈字段
- 定义 JSON Schema

交付物：

- 接口字段文档
- 示例 JSON
- 项目二输入输出边界说明

### 第 2 阶段：策略生成 MVP

任务：

- 实现自然语言目标解析
- 实现基础客群圈选
- 实现渠道和预算推荐
- 实现策略包输出

交付物：

- Strategy Agent Demo
- `/api/strategy/generate` 接口
- 可视化策略结果页面

### 第 3 阶段：可解释与追问

任务：

- 给策略结果增加推荐理由
- 支持运营人员修改预算、渠道、风险阈值
- 支持多轮追问后重算策略

交付物：

- 可解释策略报告
- 策略重算接口
- 策略状态管理

### 第 4 阶段：与项目三联调

任务：

- 输出 DeployCampaign 策略包
- 支持 C 端按 customer_id 获取单客推荐
- 接收 C 端反馈数据

交付物：

- B -> C 策略包接口
- C -> B 反馈接口
- 联调记录

### 第 5 阶段：复盘优化

任务：

- 基于反馈数据计算活动效果
- 输出复盘报告
- 生成下一轮优化建议

交付物：

- 复盘看板
- 策略优化建议
- 项目二最终汇报材料

## 5. 项目二能力体现

项目二主要锻炼以下能力：

1. 业务理解能力：理解银行信用卡营销中的客群、产品、渠道、权益、合规和 ROI。
2. 算法建模能力：客户分群、响应率预测、转化率预测、风险预测、推荐排序。
3. Agent 编排能力：用 LangGraph/MCP 串联目标理解、知识查询、策略生成、解释和反馈。
4. 工程落地能力：FastAPI 接口、JSON Schema、Redis 状态、前后端联调。
5. 可解释 AI 能力：不仅给结论，还能说明推荐依据、风险和替代方案。
6. 协作接口能力：承接项目一数据，向项目三下发策略，接收反馈并优化。

# 群像刻画方法调研报告

## 1. 结论先行

项目 B 的“群像刻画”不是给客户贴几个静态标签，也不是单纯跑一次聚类算法。它的目标是：在营销授权、频控、投诉风险和产品规则等边界内，把一批客户转成运营人员能执行、能解释、能衡量效果的目标客群。

对本项目，建议采用“规则准入 + 多维评分 + 可解释群像 + 实验反馈”的组合式方案：

```text
项目一客户洞察
    -> 合规/频控/风险准入
    -> 价值、生命周期、偏好、意图特征加工
    -> 候选客户评分与排序
    -> 按策略目标形成客群
    -> 生成群像报告、排除说明、推荐理由
    -> 项目三触达并回传反馈
    -> A/B 实验与增量效果复盘
```

这比“只做 K-Means”更符合银行营销的真实工作方式：运营人员需要知道谁可以触达、为什么选他、触达什么、用什么渠道、预期收益和风险是什么。

## 2. 什么是群像刻画

群像刻画是对“一个客群整体”进行总结，而不是展示单个客户详情。一次合格的群像至少回答六个问题：

1. 这批人是谁：规模、生命周期、价值层级、典型标签。
2. 他们最近在做什么：消费、浏览、咨询、点击、权益领取、拒绝等行为。
3. 为什么值得触达：与当前产品/活动目标的匹配原因。
4. 适合给什么：产品、权益、文案重点、触达时机。
5. 不能给谁：未授权、频控命中、高投诉风险、产品不适配等排除原因。
6. 预计效果如何：覆盖人数、响应/转化概率、预估成本、预估 ROI，并在活动后验证。

例如，针对“信用卡分期促活”活动，输出不应只有“客群 3，人数 2,000”。更像：

> 高消费、App 活跃、近期浏览过分期入口且营销授权有效的年轻活跃客户。该群体近 30 天平均消费较高，线上支付和大额消费占比高，适合优先通过 App Push 触达；因投诉风险低、近 7 天触达次数未超限而入选。建议保留 10% 对照组，验证分期优惠带来的增量转化。

## 3. 可选方法全景

| 方法 | 通俗解释 | 适合解决的问题 | 优点 | 局限 | 本项目建议 |
| --- | --- | --- | --- | --- | --- |
| 规则分群 | 按业务条件筛人，如“近 30 天消费 > 5,000 且同意营销” | 首版圈选、合规准入 | 透明、可控、容易展示 | 难发现复杂模式 | 必做，作为底座 |
| RFM / RFMC | 看最近是否消费、消费频率、金额，再补充信用卡使用率/价值 | 客户价值与活跃度分层 | 简单、稳定、业务易懂 | 不含实时意图和因果效果 | MVP 推荐 |
| 生命周期分群 | 新客、成长、活跃、沉睡、流失风险 | 不同阶段采用不同策略 | 很贴合运营动作 | 需要定义阶段规则 | MVP 推荐 |
| 标签与行为偏好 | 从消费品类、渠道、权益领取、浏览咨询提炼偏好 | “给什么、在哪触达” | 可解释、便于文案和渠道匹配 | 标签质量决定上限 | MVP 推荐 |
| 无监督聚类 | 让算法根据相似性自动分组，如 K-Means、GMM、层次聚类 | 发现未知客群 | 能发现人工规则遗漏的模式 | 簇不一定可运营，结果受特征和参数影响 | 第二阶段探索 |
| 监督学习评分 | 预测响应、转化、流失或投诉风险 | “谁更可能转化/投诉” | 可直接排序和估计概率 | 需要足够历史标签 | 有历史数据后引入 |
| 倾向/增量模型（Uplift） | 预测“因为触达而额外产生的转化” | 避免给本来就会买的人浪费资源 | 最贴近营销增量价值 | 需要处理组、对照组和严谨实验 | 项目亮点，后续引入 |
| 时序/实时意图 | 根据最近搜索、咨询、浏览、交易等事件识别当前需求 | “现在要不要推、推什么” | 时效性强，适合 Agent 联动 | 事件流与时效要求更高 | 本项目应做轻量版 |
| 图谱/相似人群 | 用客户-产品-场景-权益关系找相似客户 | 交叉营销和冷启动 | 关系表达强 | 复杂度较高、演示成本高 | 可作为扩展方向 |

## 4. 各方法如何落到银行信用卡营销

### 4.1 规则准入：先回答“能不能触达”

这是任何建模之前的硬边界，输出必须可审计。建议设置如下排除规则：

| 排除维度 | 示例规则 | 原因 |
| --- | --- | --- |
| 营销授权 | `marketing_consent = false` | 未获得营销同意，不进入候选池 |
| 频控 | 近 7 天触达次数超过阈值 | 避免打扰和投诉 |
| 投诉风险 | `complaint_risk` 超过阈值 | 保护客户体验与品牌风险 |
| 产品适配 | 已持有目标产品或不满足产品准入条件 | 避免无效推荐 |
| 风险/合规 | 风险等级、黑名单、监管限制命中 | 防止不当营销 |

注意：排除统计本身就是群像报告的重要内容。B 端应输出“候选 10,000 人，因未授权排除 1,200 人、频控排除 600 人、投诉风险排除 180 人，最终可触达 8,020 人”，而不是只给最终名单。

### 4.2 RFM / RFMC：回答“谁有价值、谁还活跃”

RFM 是营销中常用的基础分层方法：

- R（Recency）：距最近一次有效消费/互动过去多久。
- F（Frequency）：一段时间内消费或互动次数。
- M（Monetary）：一段时间内消费金额或贡献金额。
- C（Credit-card extension）：可加入信用卡特有的额度使用率、分期历史、权益使用率、利润贡献或 CLV。

建议不要把它做成单一总分，而是保留分项标签。例如“高价值活跃”“高消费待激活”“低频高客单”“沉睡唤醒候选”，因为运营动作不同。

适用案例：

- 分期营销：高 M、高额度使用率、近期大额消费、历史分期偏好高。
- 权益激活：高价值但权益领取率低、App 活跃客户。
- 唤醒营销：过去价值高、近期 R 变差、仍有营销授权的客户。

### 4.3 生命周期分群：回答“此刻应该做什么”

建议基于开户时长、近 30/90 天交易、App 活跃、近期咨询与流失信号定义客户阶段：

| 生命周期 | 典型信号 | 可选策略 |
| --- | --- | --- |
| 新客 | 开卡不久、首刷未完成 | 首刷引导、基础权益教育 |
| 成长 | 有消费但使用深度不足 | 场景权益、额度/分期教育 |
| 活跃 | 高频消费、App 活跃 | 交叉销售、精细权益匹配 |
| 沉睡 | 近期消费和活跃度下降 | 唤醒、低打扰触达 |
| 流失风险 | 长期不活跃、负反馈上升 | 服务优先、谨慎营销或停止营销 |

生命周期比“年龄、城市”等静态属性更能决定当下的营销策略。

### 4.4 标签与意图：回答“给什么、什么时候给、在哪给”

项目一已定义 `tags`、`intent_vector`、`event_sequence`，正好可用于这部分。B 端应把散乱事件压缩为可解释特征：

| 原始数据 | 可加工出的特征 | 用途 |
| --- | --- | --- |
| 消费流水 | 餐饮/商旅/线上支付/大额消费偏好 | 权益和产品匹配 |
| App 浏览、搜索、咨询 | 分期意图、权益意图、出行意图 | 判断当前触达主题 |
| Push/SMS/企业微信历史 | 渠道偏好、打开率、拒绝率 | 渠道路由 |
| 近期触达记录 | 频控状态、疲劳度 | 控制打扰 |
| 客服/投诉事件 | 体验风险、服务优先级 | 排除或降频 |

首版不必做复杂大模型特征工程。可先约定一组业务标签，如 `installment_interest`、`travel_preference`、`app_active`、`high_spend`、`benefit_sensitive`，并清晰记录标签来源和更新时间。后续再使用 LLM 对咨询摘要或事件文本做结构化意图抽取。

### 4.5 无监督聚类：回答“有没有我们没想到的新客群”

聚类是把特征相似的客户自动放进同一组。常见选择：

- K-Means：速度快、易实现；适合已数值化且大致呈团状的数据。
- Gaussian Mixture Model（GMM）：允许客户以概率属于多个群，更灵活。
- 层次聚类：适合展示群组层级，但数据量大时成本更高。
- DBSCAN/HDBSCAN：能识别异常点，但参数更敏感。

银行营销中，聚类不能直接决定投放。正确做法是：先用它发现模式，再由业务人员给簇命名、检查可解释性、验证规模和收益，最终把有价值的簇固化为可审计的运营规则。

首版可用“RFM + 生命周期 + 行为标签”的规则群像替代聚类；有至少数千条较完整样本后，再用 K-Means 对照验证。聚类数量可以结合轮廓系数、稳定性和业务可执行性共同选择，不能只看算法指标。

### 4.6 响应/转化/风险评分：回答“优先排谁”

当项目三积累活动日志后，可训练三类监督模型：

- 响应模型：客户是否打开、点击、回复。
- 转化模型：客户是否办理分期、领取权益、完成目标行为。
- 风险模型：客户是否投诉、退订、产生负反馈。

可从逻辑回归、LightGBM/XGBoost 开始。B 端最终排序可采用可解释的多目标公式：

```text
策略优先级 = 0.35 × 转化概率
           + 0.25 × 预估客户价值
           + 0.20 × 实时意图匹配度
           + 0.10 × 渠道匹配度
           - 0.10 × 投诉风险
```

这里的权重不是“算法真理”，而是可配置的业务策略。MVP 应把每项得分和命中理由一并返回，方便展示可解释性。

### 4.7 增量模型（Uplift）：回答“营销是否真的带来额外转化”

普通转化模型找的是“谁最可能转化”；但这批人可能不看营销也会转化。Uplift 模型估计的是“给这个客户触达，相比不触达，额外增加多少转化概率”。它需要活动中的处理组和对照组数据。

用四类客户可以直观解释：

| 人群 | 特征 | 策略 |
| --- | --- | --- |
| 可劝服者 | 触达后更可能转化 | 优先触达 |
| 自然转化者 | 不触达也可能转化 | 少花营销成本 |
| 无感者 | 触达与否差别不大 | 降低优先级 |
| 反感者 | 触达后反而更差/更容易投诉 | 排除或停止触达 |

相关研究将这种增量定义为个体处理效应（ITE），强调处理组与对照组比较；也有研究将预估增量与业务价值/利润一起评价，而不是只看点击率或转化率。[Causal Inference and Uplift Modelling: A Review of the Literature](https://proceedings.mlr.press/v67/gutierrez17a.html)；[Uplift Modeling with Value-Driven Evaluation Metrics](https://www.sciencedirect.com/science/article/abs/pii/S0167923621001585)。

在训练营 Demo 中，不需要一开始真正训练复杂 Uplift 模型，但必须设计并输出 `experiment_plan`：例如 90% 策略组、10% 随机对照组，活动后比较增量转化、增量收益、投诉率。这会让项目明显更像一个完整的智能决策系统。

## 5. 推荐的项目 B 实现方案

### 5.1 第一版（必须完成）

采用规则与评分驱动的群像刻画，使用现有 A -> B 合同中的字段：

```text
CustomerProfile
  marketing_consent, risk_level, complaint_risk, recent_contact_count
  monthly_spend, credit_limit_usage, lifecycle_stage, value_level
  tags, preferred_channel

IntentVector + EventSequence
  近期产品意图、浏览/咨询/点击等实时行为
```

功能清单：

1. 可触达筛选：授权、风险、投诉、频控和产品准入。
2. 多维打分：价值、活跃度、产品匹配、意图、渠道匹配、风险。
3. 形成策略客群：按营销目标选取 Top N 或高于阈值的客户。
4. 输出群像报告：规模、标签占比、生命周期分布、渠道偏好、入选理由、排除统计、预估效果。
5. 输出给项目三的策略包：客群规则、单客推荐、触达渠道、频控和实验配置。

建议的首版客群命名：

- `高价值活跃分期潜力客群`
- `权益敏感 App 活跃客群`
- `高价值沉睡唤醒客群`
- `商旅偏好权益推荐客群`
- `服务优先低打扰客群`（只给服务提醒，不做强营销）

### 5.2 第二版（有历史反馈后）

1. 对点击、转化、投诉训练基础预测模型。
2. 按渠道分别估计响应概率，做渠道排序。
3. 使用 SHAP 等方法输出全局/群体解释，避免只有黑盒分数。
4. 以聚类发现新群体，但仍以规则固化上线。
5. 引入 A/B 对照组和 Uplift 思路，将“预估转化”升级为“预估增量收益”。

### 5.3 第三版（扩展亮点）

1. 使用时序特征或流式事件，实时调整客户的意图和触达时机。
2. 多策略/多权益 Uplift：不只是判断“要不要推”，还判断“推哪种权益”。
3. 约束优化：在预算、渠道容量、频控、投诉风险约束下最大化预估增量收益。
4. 用 LLM 将群像结论、策略理由和风险提示生成人类可读的运营报告，但不让 LLM 绕过规则和合规校验。

## 6. 群像报告的接口产物建议

建议在现有 `MarketingPlan` 中新增 `audience_profile` 和 `exclusion_summary`，同时在 B -> C 策略包中保留 `audience_insight`：

```json
{
  "audience_profile": {
    "segment_name": "高价值活跃分期潜力客群",
    "eligible_count": 8020,
    "targeted_count": 2000,
    "lifecycle_distribution": {"active": 0.72, "growth": 0.28},
    "top_tags": ["high_spend", "app_active", "installment_interest"],
    "channel_preference": {"app_push": 0.61, "wechat": 0.24, "sms": 0.15},
    "avg_scores": {
      "value": 0.81,
      "intent_match": 0.76,
      "conversion": 0.19,
      "complaint_risk": 0.04
    },
    "business_interpretation": "高消费且近期表现出分期意图，优先采用 App 触达。"

```

此对象只表达群体统计和策略理由，不把全量个人信息下发给项目三。单客触达只传递项目三真正执行所需的 `customer_id`、推荐动作、渠道和频控信息，符合最小必要原则。

## 7. 评估指标：不要只看准确率

| 层面 | 指标 | 说明 |
| --- | --- | --- |
| 数据质量 | 完整率、时效性、标签覆盖率 | 画像是否可靠 |
| 分群质量 | 覆盖率、群间差异、群内一致性、稳定性 | 群体是否有区分度 |
| 模型效果 | AUC、PR-AUC、校准度 | 适用于响应/转化/风险预测 |
| 经营效果 | 触达率、点击率、转化率、ROI、增量收益 | 策略是否值得做 |
| 体验与风险 | 退订率、投诉率、频控命中率 | 是否造成打扰或风险 |
| 可解释性 | 规则命中率、理由覆盖率、人工复核通过率 | 运营人员是否能理解和采纳 |

对增量策略，建议优先比较“策略组与对照组的转化差、收益差和投诉差”，而不是只比较策略组内部的转化率。Uplift 研究的核心也正是估计触达相对于不触达带来的因果增量。[Ensemble Methods for Uplift Modeling](https://link.springer.com/article/10.1007/s10618-014-0383-9)。

## 8. 银行场景的合规设计要求

群像刻画属于基于个人信息的自动化决策/营销应用，合规不是最后加一个提示词，而应嵌入整个流程：

1. 以营销同意为准入条件，客户不同意营销不应影响其正常金融服务。
2. 做数据最小化：B 端优先使用去标识化 `customer_id`、聚合特征和标签，而非无必要的原始明细。
3. 每次圈选记录数据版本、规则版本、模型版本、命中原因和操作者，形成审计日志。
4. 对高风险场景保留人工复核和停止触达能力。
5. 给出清晰理由与退出路径，避免不合理差别待遇和过度营销。

《个人信息保护法》要求自动化决策保持透明、公平公正，并赋予个人对重大影响自动化决定要求说明和拒绝仅自动化决定的权利；金融消费者信息用于营销时，也应提供自主同意选择。[工业和信息化部：个人信息保护法](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)；[中国人民银行金融消费者权益保护实施办法](https://www.yw.gov.cn/art/2020/11/20/art_1229129839_1710069.html)。

## 9. 本项目的最终选择

训练营项目应把“复杂算法”用在最能体现决策价值的地方，而不是为了算法而算法。推荐路线为：

```text
现在：规则准入 + RFM/生命周期 + 标签/意图 + 多维评分 + 群像报告
下一步：响应/转化/投诉预测 + 渠道排序 + A/B 对照组
```
